# xwGIT

个人资料库的公开说明页。这里只放规范文档，实际文件存放在私有仓库。

## 仓库划分

| 类型       | 可见性 | 放什么            |
| -------- | --- | -------------- |
| 说明页（本仓库） | 公开  | 目录约定、命名规范、使用说明 |
| 资料库      | 私有  | 文档、表格、脚本及其历史版本 |

> 公开仓库的内容对所有人可见。涉及客户信息、内部数据或个人信息的文件一律放私有仓库，不要提交到这里。

## 目录结构约定

资料按用途分目录，不按时间或人员分：

```text
docs/       说明文档、模板、规范
data/       原始数据、台账
reports/    输出成品（文档、图表）
scripts/    处理脚本与小工具
archive/    已归档、不再维护的内容
```

目录名统一用英文小写；新增目录先在本页登记。

## 文件命名

- 格式：`YYYYMMDD_主题_版本.扩展名`，例如 `20261115_月度资料_v1.pptx`
- 日期用 8 位数字，按名称排序即为时间顺序
- 版本号从 v1 起递增，不复用旧号
- 不用「最终版」「副本」「新建文件夹」这类含糊词

## 提交规范

每次提交只做一件事，说明写清改了什么、为什么改：

```text
新增 2026 年 11 月资料模板
修正 10 月台账的统计口径
归档 2025 年历史文件
```

完成一个可独立使用的改动就提交一次，不要攒到月底一次性上传。

## 版本回溯

每次提交都是一个可恢复的快照。文件改坏或被覆盖时，找到对应提交即可恢复，也能对比两个版本之间的差异。Markdown、CSV、脚本等文本类文件可以逐行对比；PPT、Excel 等二进制文件只能整份恢复，因此重要内容建议同时保留一份文本台账。

## 使用约定

- 敏感资料只进私有仓库，公开仓库只放说明
- 视频、压缩包等大文件另用网盘，不放这里
- 提交前确认没有误带临时文件或个人信息
- 日常提交、读取、回滚可通过 WorkBuddy 用自然语言完成，不必记命令
